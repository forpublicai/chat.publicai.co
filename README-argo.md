# ArgoCD Deployment Setup

This repository contains an ArgoCD configuration using the "App of Apps" pattern. This allows you to manage all your Kubernetes deployments declaratively through GitOps.

## Manual Steps for Setup

Before running the GitHub Action to deploy the ArgoCD applications, please ensure the following manual steps and validations have been completed:

1. **Update Repository URLs**: 
   In both `argo/bootstrap/staging-bootstrap.yaml` and `argo/apps/staging/simple-pod.yaml`, replace the `repoURL` value (`https://github.com/forpublicai/chat.publicai.co`) with your actual GitHub repository URL if it differs.

2. **Verify Cluster Name in GitHub Actions**:
   In the new `.github/workflows/deploy-argo.yaml` file, the cluster name is placeholder (`staging-cluster`). You must update this to match the exact EKS cluster name generated by your Terraform (e.g., `staging-publicai-eks-cluster`).

3. **Verify AWS Role ARN in GitHub Actions**:
   Make sure that `secrets.AWS_ROLE_ARN` used in the new Action has the necessary permissions to authenticate to EKS and run `kubectl apply`.

4. **Ensure ArgoCD is Accessible**:
   Your Terraform sets up ArgoCD as a `ClusterIP`. For UI access, you'll need to port-forward or configure an Ingress/VPN as noted in the Terraform comments. To get the admin password, you can run:
   `kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath="{.data.password}" | base64 -d`

## How it works

1. **Terraform**: Bootstraps the EKS cluster and installs the ArgoCD controller into the `argocd` namespace.
2. **GitHub Action (`staging-terraform.yaml`)**: On a push of a tag (e.g., `v1.0.0`), it authenticates to EKS and applies `argo/bootstrap/staging-bootstrap.yaml`.
3. **App of Apps (`staging-bootstrap.yaml`)**: Points to the `argo/bootstrap/staging/` directory in this repository.
4. **Simple Pod App (`simple-pod.yaml`)**: Tells ArgoCD to deploy the Helm chart located in `charts/simple-pod` using the `values.yaml` configuration.

From that point on, any updates pushed to the repository in `charts/simple-pod` or `argo/apps/staging` will be automatically synced to the cluster by ArgoCD without needing to run the GitHub action again!
